# 日志格式 v1

每条有效记录代表一次请求处理的最终结果。相同请求的开始、过程、结束不应分别当成三次请求写入。此项目使用自行生成的模拟设备数据。

```text
timestamp device_id level event_code duration_us
1700000000 dev01 INFO REQ_OK 100
```

第一行是格式说明，不是实际文件的表头。实际文件不含表头或注释。

| 字段 | 类型与范围 | 含义 |
|---|---|---|
| timestamp | `int64_t`，0～9223372036854775807 | Unix 时间戳，单位为秒 |
| device_id | `[A-Za-z0-9_-]+` | 设备标识，区分大小写 |
| level | `INFO`、`WARN`、`ERROR` | 日志级别，必须大写 |
| event_code | `[A-Za-z0-9_-]+` | 事件码，区分大小写，不设固定事件列表 |
| duration_us | `uint64_t`，0～18446744073709551615 | 处理耗时，单位为微秒 |

## 文本和数字规则

- 使用 UTF-8，无 BOM。合法字段都是 ASCII 字符；中文设备名暂不支持。
- 一行一条记录，恰好五个字段。字段间允许连续 ASCII 空白，常用空格、制表符；允许首尾空白。解析器识别空格、`\t`、`\r`、`\n`、`\v`、`\f`。
- 文件读取按 LF 分行，接受 Linux 的 LF 和 Windows 的 CRLF。最后一行可以没有换行符。仅有 CR 的旧式换行不作为分行符。
- 数字只能包含 `0`～`9`，允许零和前导零；不接受正负号、小数、十六进制、科学计数法或尾随字符。
- 先检查字段数，再按字段从左到右校验。每条坏行只报告第一个错误。
- 不要求记录按时间排序；重复合法行分别计数，暂不去重。
- 不根据事件码反推级别，例如 `INFO TIMEOUT` 在格式上合法；错误统计以 `level == ERROR` 为准。

## 错误处理与计数

| 情况 | 行为 |
|---|---|
| 空行、缺字段、多字段 | 非法记录，跳过并继续 |
| 数字格式不合法 | 非法记录，说明对应字段 |
| 数字超出目标类型范围 | 非法记录，报告越界 |
| 非法设备 ID、级别或事件码 | 非法记录，说明对应字段 |
| 空文件 | 正常完成，三项计数均为 0 |
| 文件不存在、路径是目录、无法打开 | 报文件错误，不进行统计，退出码 3 |
| 读取中途失败 | 报文件错误，输出已完成行的部分计数，退出码 3 |

正常完成时：`read_lines == valid_records + invalid_records`。行号从 1 开始。

文件末尾的单个换行符只是上一行的结束标记，不会额外计一个空行；两个连续换行符之间才形成空行。

格式错误写入标准错误流，例如：

```text
data/sample.log:6: expected exactly 5 fields
```

## 后续统计口径（尚未实现）

- 先筛选有效记录，再按设备统计。错误数指其中 `level == ERROR` 的数量。
- 错误率 = 纳入统计的错误数 / 纳入统计的记录数；只筛选 ERROR 时，统计的是该子集。
- 平均耗时包含成功与失败记录；累计总耗时与记录数，最后求平均，不能直接平均多个分组的平均值。
- 事件 Top-K 按频次降序，频次相同按事件码字典序升序。
- 多线程先合并每种事件的完整计数，再计算全局 Top-K。
- 统计阶段还需检查累计耗时的溢出：单条耗时合法，并不保证多条求和不会越界。
